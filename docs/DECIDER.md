# 判断规范（DECIDER）

把「要不要跟进」从 `prompts/review.md` 里抽出来，做成可以单独喂场景、单独评估的一层。
代码实现：`scripts/decide.py`；判断题本身由 LLM 做，确定性部分（到期、冷却、夜间、上限）由代码做。

## 输入

```json
{
  "now": "2026-10-31T09:30:00+09:00",
  "history": [{"t": "...", "role": "user|assistant", "text": "..."}],
  "followups": [
    {"id": 3, "why": "care", "subject": "喉咙痛", "quote": "哪几种喉咙药好",
     "revisit_at": "2026-10-31T09:00+09:00", "sent_at": null, "checks": 0}
  ]
}
```

## 第一步：确定性闸门（代码）

| 闸门 | 条件 | 效果 |
|---|---|---|
| 夜间 | 本地 23:00–08:00 | 可以判断，但 `message` 必须为 null |
| 冷却 | 距上次发送 <90 分钟 | 同上 |
| 到期 | `revisit_at <= now` 且 `sent_at < revisit_at` | 才算 due |
| 无变化 | 与上次讨论相比没有新信息 | 该条只能 silent |
| 上限 | 一条消息 ≤3 项、≤6 行 | 超出截断 |

## 第二步：判断题（LLM）

### 什么值得跟进

过一阵子回来看一眼，会让他觉得**有用**，或者觉得**被记得**。两种由来：

- `care`：他说喉咙痛、面试、等结果 → 第二天问一句「好点没」。**不需要有行动价值。**
- `utility / risk / curiosity`：天气、价格、说明书、新闻、后续动态。

### 两条评分线（各自独立，任一过线即可）

```
实用线   相关0-2 + 变化0-2 + 可行动0-2 + 时效0-2 − 风险0-2   ≥5 发
关心线   是真事 / 细节具体 / 时机对 / 没重复              四条全过就发
```

### 三种动作

- `silent`：不发。记一笔为什么（没变化 / 时机不对 / 已有别的渠道）。
- `act_report`：读一下就知道了（天气、价格、说明书、新闻）→ 直接查完写进消息。
- `ask`：改日历、设提醒、给别人发消息、花钱 → 只提议，不动手。

### 消息

一条消息里最多 3 项，每项 2–3 行，带 emoji 头，不带「我复盘了」「这是自动的」。

## 输出

```json
{
  "new_followups": [{"key":"throat-1030","why":"care","subject":"喉咙痛","quote":"…","revisit_at":"+12h"}],
  "decisions": [
    {"id":3,"action":"act_report","reason":"…","score":{"relevance":2,"change":1,"action":1,"timing":2,"risk":0}},
    {"id":5,"action":"silent","reason":"查了没变化"}
  ],
  "message": "💊 …" ,
  "silent_actions": ["查了天气，明天不下雨，没发"]
}
```

`message` 为 null 表示这一轮静默——这是**正常结果**，不是失败。
